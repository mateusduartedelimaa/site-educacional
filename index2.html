HTML – Fundamentos, Semântica e Boas Práticas

HTML5 não é apenas marcação, é a espinha dorsal da web semântica e acessível. Dominar suas nuances melhora SEO e a experiência de todos os usuários.

  <header>...</header>
  <nav>...</nav>
  <main>
    <article>
      <h1>Título do artigo</h1>
      <section>...</section>
      <aside>Informações complementares</aside>
    </article>
  </main>

Leis de De Morgan: ¬(p ∧ q) ≡ ¬p ∨ ¬q   |   ¬(p ∨ q) ≡ ¬p ∧ ¬q

📊 Conjuntos

Algoritmos de Busca

  • BFS (Breadth-First Search): Usa fila, encontra caminho mais curto em grafos não ponderados.
  • DFS (Depth-First Search): Usa pilha (ou recursão), útil para detecção de ciclos e ordenação topológica.
  • Dijkstra: Caminho mais curto com pesos positivos (fila de prioridade).

🔢 Indução Matemática e Recursão

A indução é usada para provar a corretude de algoritmos recursivos.

function fatorial(n) {
  if (n <= 1) return 1;        // Caso base
  return n * fatorial(n - 1);  // Passo indutivo
}

🧮 Álgebra Booleana e Circuitos Lógicos

Portas lógicas: AND, OR, NOT, XOR, NAND, NOR
Expressões booleanas simplificadas com Mapas de Karnaugh.

Propriedades

  • Idempotência: A + A = A, A · A = A
  • Elemento neutro: A + 0 = A, A · 1 = A
  • Complemento: A + ¬A = 1, A · ¬A = 0

IHC – Interação Humano-Computador

IHC estuda a interação entre pessoas e computadores, visando criar sistemas usáveis, acessíveis e satisfatórios.

📌 As 10 Heurísticas de Nielsen (com exemplos)

  1. Visibilidade do status: Mostrar "Carregando..." ou barra de progresso.
  2. Correspondência com o mundo real: Ícone de lixeira para deletar.
  3. Controle e liberdade: Botão "Desfazer" após excluir.
  4. Consistência e padrões: Links azuis sublinhados.
  5. Prevenção de erros: Confirmar antes de apagar permanentemente.
  6. Reconhecimento em vez de memorização: Menus dropdown visíveis.
  7. Flexibilidade e eficiência: Atalhos de teclado (Ctrl+S).
  8. Design estético e minimalista: Evitar informações irrelevantes.
  9. Ajudar a reconhecer/diagnosticar erros: Mensagens claras como "Senha incorreta".
  10. Ajuda e documentação: FAQ ou tooltips.

📏 Leis de UX

LeiDescriçãoImplicação prática
FittsTempo para alcançar alvo depende da distância e tamanhoBotões grandes e próximos
HickTempo de decisão aumenta com número de opçõesSimplificar menus, usar agrupamento
JakobUsuários passam a maior parte do tempo em outros sitesSeguir convenções estabelecidas
Miller (7±2)Capacidade da memória de trabalho é limitadaAgrupar informações em chunks
ParkinsonToda tarefa se expande até preencher o tempo disponívelDefinir prazos claros

🧪 Métodos de Avaliação de Usabilidade

  • Think Aloud: Usuário verbaliza pensamentos durante tarefa.
  • Avaliação Heurística: Especialistas inspecionam interface com base em heurísticas.
  • Teste A/B: Compara duas versões com usuários reais.
  • SUS (System Usability Scale): Questionário de 10 itens (escala Likert).
  • Eye Tracking: Rastreamento ocular para analisar atenção visual.

♿ Diretrizes WCAG 2.1 (Acessibilidade)

  • Perceptível: Texto alternativo, legendas, contraste mínimo (4.5:1).
  • Operável: Navegação por teclado, tempo suficiente, evitar flashes.
  • Compreensível: Idioma claro, navegação consistente, ajuda para erros.
  • Robusto: Compatível com tecnologias assistivas.

🎭 Affordance e Signifiers

  • Affordance: O que um objeto "convida" a fazer (ex: botão parece clicável).
  • Signifiers: Indicadores visuais que comunicam a affordance (ex: sombra, ícone de mão).

🧠 Carga Cognitiva e Modelos Mentais

Carga cognitiva: Esforço mental exigido. Interfaces devem reduzir a carga extrínseca.

Modelo mental: Representação que o usuário tem do sistema. Deve-se alinhar o design ao modelo mental do usuário.

📱 Design Responsivo e Mobile First

  • Priorizar conteúdo essencial em telas pequenas.
  • Alvos de toque com pelo menos 44x44px.
  • Gestos comuns: deslizar, pinçar.
